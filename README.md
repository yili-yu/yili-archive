# yili 私人档案站

这是一个可直接部署到 GitHub Pages 的纯静态私人档案站。它不依赖数据库，也不会自动上传电脑中的任何文件。

## 已包含的功能

- 密码初始化与解锁
- AES-GCM 加密保存，密码通过 PBKDF2 派生
- 会话、日记、资料及其他记录
- 时间线
- 自定义问题组，一条记录可属于多个问题组
- 全文搜索和类型筛选
- 记录新增、编辑、删除
- 在线文件链接与本地文件路径（均为可选）
- 加密密库导入、导出与修改密码
- 桌面端与移动端响应式界面

## 第一次使用

1. 在本目录启动静态服务器，例如：

   ```powershell
   python -m http.server 8080
   ```

2. 打开 `http://localhost:8080`。
3. 设置密码。数据会加密后保存在当前浏览器的 localStorage 中。
4. 在“设置”中定期导出加密密库备份。

不要直接双击 `index.html`；浏览器对 `file://` 页面和加密接口有额外限制，请通过静态服务器或部署后的 HTTPS 地址访问。

## 部署为二级站点

仓库根目录已经包含 `CNAME`，默认域名为：

```text
archive.yiliyu.com
```

将整个目录作为独立仓库部署到 GitHub Pages，并在 DNS 中为 `archive` 添加相应记录即可。

## 数据保存方式

默认情况下，实际档案只保存在使用站点的浏览器中。站点源码不包含任何私人材料。

如需跨设备使用：

1. 在“设置”中导出 `yili-archive-vault.json`；
2. 在另一台设备的登录页选择“导入密库”；
3. 使用原密码解锁。

也可以将导出的密库重命名为 `vault.json`，替换 `data/vault.json` 后随站点部署。服务器看到的仍是密文；更新内容后需要再次导出并替换。

## 文件是否上传

每条记录分别支持：

- `在线文件链接`：文件已经上传时填写；
- `本地文件路径`：文件只留在电脑上时填写；
- 两者均不填写：只保存记录正文。

网站不会读取或上传本地路径指向的文件。浏览器通常也不能从在线页面直接打开 `E:\...` 一类路径，因此站点提供复制路径按钮。

放入 `files/` 并随站点部署的附件本身不会自动加密；若附件也需要保密，应先在本地加密，或者只保留本地路径。

## 安全边界

本项目的档案数据经过浏览器端加密，比单纯隐藏页面可靠；但它仍是个人静态档案工具，不代替专业密钥管理和多因素认证。请保留独立备份。忘记密码后无法恢复密库内容。
